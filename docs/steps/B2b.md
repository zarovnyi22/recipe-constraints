# B2b — розв'язувач і «що послабити» (модель: Opus)

Прочитай `docs/SPEC.md` §4.
- `app/solver.py`: solve(constraints) → Recipe | Infeasible; округлення з повторною
  перевіркою і ε-запасом; еластичний LP; альтернативи «достатньо змінити одне з…»
  (кожна перевірена повторним розв'язком → verified); мінімальний конфліктний набір.
- Приклад з умови як структурований spec (тест, без LLM): полуничний йогурт без молока,
  білок ≥ еталону, ≤ 45 грн/кг, reduced_sugars → або рецептура, або пояснення; результат
  запиши в NOTES («Розв'язувач»).
- Тести: здійсненний випадок; свідомо нездійсненний (ціна 5 грн/кг) → послаблення ціни з
  числом; два конфліктні (sugar_free + sweetness_min без підсолоджувачів) → конфлікт;
  округлення не ламає щільне обмеження; Σ = 1000,0 г рівно.
Ворота: `make test && make lint`.
Особливі пункти рев'ю: чи може запропоноване послаблення бути неперевіреним; чи послаблюються
жорсткі обмеження.
Коміт: `feat(b2b): LP solver, rounding, relaxations`.
