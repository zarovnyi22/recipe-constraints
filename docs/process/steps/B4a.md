# B4a — набір запитів (модель: Opus)

Прочитай `docs/SPEC.md` §7.
1. dev (~15) пишеш ти: формат `eval/requests/dev/<id>.yaml`; суміш feasible / infeasible
   (з очікуваним конфліктом) / partial / unsupported.
2. test (~20) пише **субагент**, якому дай ЛИШЕ умову таски (абзац з CLAUDE.md) і формат
   файлу; він не бачить data/, шаблонів і коду. Попроси імітувати вечірні запити PM:
   різні продукти, суперечливі вимоги, порівняння зі «звичайним», дешеві ціни, твердження,
   алергени, веган, неіснуючі категорії, розмиті формулювання. `expected` він заповнює за
   здоровим глуздом; де не впевнений — `expected.notes`.
   Ти test-файли не відкриваєш (лише валідуєш схему скриптом, який друкує кількість).
Ворота: валідатор схеми; `make test`.
Коміт: `feat(b4a): dev and test request sets`.
